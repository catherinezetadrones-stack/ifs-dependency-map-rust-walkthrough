    What the program is for

    IFS Cloud ships its source as a Core folder that you never edit. Your company's changes live in a separate Cust folder, mostly as -Cust files that layer over Core files of the same name. The tool reads both folders, builds one dependency graph across them, and reports problems that only show up once your Cust layer is applied: include cycles, duplicate definitions, a missing @Override, undeclared component connections, columns made ambiguous, datatypes that don't match, and what an IFS upgrade changed under your customizations. It never writes to either folder.

    The data model in one picture

    Everything ends up in one Index struct (model.rs, ). It owns seven vectors, and every link between them is a number or a string id, never a Rust reference:

    files: Vec<SourceFile>one per file read · root = Core or Cust · unit → "u12"
    units: Vec<Unit>logical name: X.fragment + X-Cust.fragment = one unit · files → [19, 35]
    objects: Vec<Object>a declaration: entity, command, procedure… · unit → "u12", file → 35, base → "o40"
    relations: Vec<Relation>a database table or view, by name · defs → files and lines
    edges: Vec<Edge>from/to are ids of a unit (u), object (o) or relation (r). Five kinds link units (include, uses_projection, implicit_include, implements, calls). Ten link objects (reference, array, enumeration, entityset_for, binds, overrides, calls_operation, implemented_by, invokes, reads).
    components: Vec<Component>SHPORD, MPCCOM… with deploy.ini connections
    findings: Vec<Finding>rule, severity, message · nodes → ids · edges → edge numbers · location → file + line · evidence and a suggested fix

    1. The most important design decision in the codebase. A Unit doesn't hold references to its files (Vec<&SourceFile>). It holds their positions in Index.files. See the box below.
    2. #[derive(Default)] on a struct works when every field has a default: empty Vecs, None, 0. Later code writes Index { version: 1, ..Default::default() } (struct update syntax) to set a few fields and default the rest.
    3. A fully qualified path, crate::stamp::Stamp, used inline instead of a use at the top. crate:: always means "the root of this crate".
    4. Doc comments (///) attach to the next item and show up in cargo doc and editor hovers. //! (as in lib.rs) documents the module that contains it.
    5. &id[1..] slices off the first byte. That's safe because ids are ASCII (u12, o40). On a multi-byte first character it would panic. parse() infers its target type (usize) from the function's return type, and unwrap_or turns a bad id into usize::MAX instead of a panic.

    The arena pattern: indices instead of references

    Index owns every Vec: files, units, objects, edges. Everything else points into those vectors by number (file: usize, files: Vec<usize>) or by string id ("u12"). If Unit held &SourceFile instead, it would need a lifetime parameter (Unit<'a>), and Index would hold references into itself. That's a self-referential struct, which safe Rust doesn't allow. The other ways out are Rc<RefCell<…>> everywhere, or indices.

    Indices win here. The data is built once and then read, ids serialize straight to JSON for the UI, and a usize is Copy, so you can hold as many as you like without borrowing anything. The cost is that the compiler no longer checks that an index is valid. A wrong number panics at runtime (out of bounds) instead of failing to compile.

    Walking folders: owned vs borrowed paths

    A complete function in 50 lines, using about a dozen everyday Rust idioms. It walks a directory tree without recursion and returns what it found plus notes about what it skipped.

    /// Walks one root (without following symlinks) and returns every file type
/// the indexer understands.
pub fn scan_root(root: &Path) -> (Vec<Scanned>, Vec<String>) {
    let mut out = Vec::new();
    let mut notes = Vec::new();
    let mut stack = vec![root.to_path_buf()];
    while let Some(dir) = stack.pop() {
        let entries = match std::fs::read_dir(&dir) {
            Ok(e) => e,
            Err(e) => {
                notes.push(format!("skipped {}: {e}", dir.display()));
                continue;
            }
        };
        for entry in entries.flatten() {
            let Ok(ft) = entry.file_type() else { continue };
            let path = entry.path();
            let name = entry.file_name().to_string_lossy().into_owned();
            if ft.is_dir() {
                if !(name.starts_with('.') || name == "node_modules" || name == "target") {
                    stack.push(path);
                }
                continue;
            }
            if !ft.is_file() {
                continue;
            }
            let Some(kind) = FileKind::from_path(&path) else { continue };
            let (size, modified) = entry.metadata().map(|m| crate::stamp::of(&m)).unwrap_or((0, 0));
            let rel_path = path.strip_prefix(root).unwrap_or(&path).to_path_buf();
            let path_component = if rel_path.components().count() > 1 {
                rel_path
                    .components()
                    .next()
                    .and_then(|c| c.as_os_str().to_str())
                    .map(|s| s.to_ascii_uppercase())
            } else {
                None
            };
            out.push(Scanned {
                rel: rel_path.to_string_lossy().replace('\\', "/"),
                abs: path,
                kind,
                path_component,
                size,
                modified,
            });
        }
    }
    out.sort_by(|a, b| a.rel.cmp(&b.rel));
    (out, notes)
}
    1. The signature: borrow the input (&Path), return owned output (Vecs). Returning a tuple is the light alternative to a dedicated struct when there are two results.
    2. to_path_buf() makes an owned copy, because the stack has to own its entries. Later entries come from entry.path(), which returns new PathBufs.
    3. while let Some(dir) = stack.pop() is iterative depth-first search. pop() moves the PathBuf out of the Vec into dir, and the loop ends when it returns None.
    4. Matching on a Result to log the error and continue. This is the "keep going on errors" style. A ? here would abort the whole scan because one folder was unreadable.
    5. read_dir yields io::Result<DirEntry> items. Result implements IntoIterator (an Ok gives one item, an Err none), so .flatten() silently drops entries that failed to read.
    6. let-else (Rust 1.65): bind on success, or run a block that must diverge (continue, return, break, panic). It keeps the happy path unindented. You'll see it dozens of times in this codebase.
    7. to_string_lossy() returns Cow<str> ("clone on write"). It borrows when the OS name is valid UTF-8 and allocates only when it has to replace bad bytes. into_owned() gives you a String either way.
    8. Option and Result combinators instead of nested match: map transforms the success value, and unwrap_or supplies the fallback. The closure takes m by value and passes &m on.
    9. strip_prefix returns Result<&Path, _>, so the fallback must also be a &Path. &path is a &PathBuf, and deref coercion turns it into &Path automatically. .to_path_buf() then copies the result so it no longer borrows path, which matters on the next line.
    10. Field order matters for moves. rel is computed from rel_path (an owned copy) first…
    11. …then abs: path moves the PathBuf into the struct with no clone. If rel_path still borrowed path, this move would be rejected.
    12. sort_by takes a comparator closure returning Ordering. Sorting makes the output the same on every run, a theme throughout the project ( explains the BTreeMap side of it).

pub struct DeployIni {
    pub component: Option<String>,
    /// `[ComponentName] Description=Customer Orders`
    pub description: Option<String>,
    /// (target component, STATIC|DYNAMIC, line)
    pub connections: Vec<(String, String, usize)>,
}

pub fn parse(text: &str) -> DeployIni {
    let mut out = DeployIni::default();
    let mut section = String::new();
    for (i, raw) in text.lines().enumerate() {
        let line = raw.trim();
        if line.is_empty() || line.starts_with(';') || line.starts_with('#') {
            continue;
        }
        if line.starts_with('[') && line.ends_with(']') {
            section = line[1..line.len() - 1].trim().to_ascii_lowercase();
            continue;
        }
        let Some((k, v)) = line.split_once('=') else { continue };
        let (k, v) = (k.trim(), v.trim());
        match section.as_str() {
            "component" if k.eq_ignore_ascii_case("name") => {
                out.component = Some(v.to_ascii_uppercase());
            }
            "componentname" if k.eq_ignore_ascii_case("description") && !v.is_empty() => {
                out.description = Some(v.to_string());
            }
            "connections" if !k.is_empty() => {
                out.connections.push((k.to_ascii_uppercase(), v.to_ascii_uppercase(), i + 1));
            }
            _ => {}
        }
    }
    out
}
    1. A Vec of tuples where a struct might go. The doc comment says what each position means. That's fine for an internal type. A named struct would be clearer once more code reads it.
    2. text: &str: the caller owns the file contents. Taking &str rather than &String is idiomatic because it accepts both &String (by deref) and string literals, which is exactly what the test does.
    3. .lines().enumerate() gives (index, &str) pairs. The &strs are slices of text, so no copying.
    4. trim() also returns a sub-slice. line borrows from text, which is why it can't outlive it.
    5. Byte-index slicing, line[1..line.len() - 1]. That's safe because the first and last characters were just checked to be [ and ], which are one byte each.
    6. split_once('=') returns Option<(&str, &str)>. Here let-else destructures a tuple inside an Option.
    7. Matching a String again, via .as_str()…
    8. …with match guards: "component" if …. If the guard is false, matching falls through to the next arm, ending at _ => {}.
    9. Line numbers are 1-based for people. enumerate is 0-based, hence i + 1, a pattern repeated in every parser.

    /// Removes a trailing `-- comment` or `// comment`, ignoring them inside double-quoted strings.
pub fn strip_comment(line: &str) -> &str {
    let bytes = line.as_bytes();
    let mut in_str = false;
    let mut i = 0;
    while i < bytes.len() {
        match bytes[i] {
            b'"' => in_str = !in_str,

            .into_iter()
            .filter_map(|c| {
                let u = id_index(&objects[c].unit);
                let rank = if u == from_unit {
                    0
                } else if reach.contains(&u) {
                    1
                } else if roots.iter().any(|&r| closure(r).contains(&u)) {
                    2
                } else if for_override {
                    3
                } else {
                    return None;
                };
                Some((rank, c))
            })
            .min_by_key(|&(rank, _)| rank)
            .map(|(_, c)| c)

    Tarjan's algorithm finds strongly connected components, sets of nodes that can all reach each other, which here means include cycles. It's usually written recursively, but a chain of 200,000 includes would overflow the stack, so this version keeps its own stack of (node, position) frames.

    /// `adj[n]` lists the successors of node `n`. Returns every SCC.
pub fn tarjan_scc(adj: &[Vec<usize>]) -> Vec<Vec<usize>> {
    let n = adj.len();
    let mut index = vec![usize::MAX; n];
    let mut low = vec![0usize; n];
    let mut on_stack = vec![false; n];
    let mut stack: Vec<usize> = Vec::new();
    let mut out = Vec::new();
    let mut next = 0usize;

    for root in 0..n {
        if index[root] != usize::MAX {
            continue;
        }
        // (node, position in its successor list)
        let mut work: Vec<(usize, usize)> = vec![(root, 0)];
        index[root] = next;
        low[root] = next;
        next += 1;
        stack.push(root);
        on_stack[root] = true;

        while let Some(&mut (v, ref mut pos)) = work.last_mut() {
            if *pos < adj[v].len() {
                let w = adj[v][*pos];
                *pos += 1;
                if index[w] == usize::MAX {
                    index[w] = next;
                    low[w] = next;
                    next += 1;
                    stack.push(w);
                    on_stack[w] = true;
                    work.push((w, 0));
                } else if on_stack[w] {
                    low[v] = low[v].min(index[w]);
                }
            } else {
                work.pop();
                if let Some(&(parent, _)) = work.last() {
                    low[parent] = low[parent].min(low[v]);
                }
                if low[v] == index[v] {
                    let mut comp = Vec::new();
                    loop {
                        let w = stack.pop().unwrap();
                        on_stack[w] = false;
                        comp.push(w);
                        if w == v {
                            break;
                        }
                    }
                    out.push(comp);
                }
            }
        }
    }
    out
}
    1. adj: &[Vec<usize>], a slice, not &Vec<Vec<usize>>. A slice accepts a &Vec through deref coercion, plus arrays and sub-slices. Prefer &[T] for read-only parameters.
    2. vec![x; n] repeats a value. usize::MAX stands for "not visited", a sentinel instead of Option<usize>. It's cheaper, but the compiler won't remind you to check for it.
    3. The explicit call stack: each frame is (node, index of next successor to visit).
    4. The cleverest pattern in the repo. work.last_mut() returns Option<&mut (usize, usize)>. The pattern &mut (v, ref mut pos) matches through the mutable reference: v is copied out, and ref mut pos binds a &mut usize pointing at the second field inside the Vec.
    5. *pos += 1 moves the frame's cursor forward in place.
    6. work.push(…) needs &mut work while pos still points into it. That's legal because pos's last use was line 29, so NLL has already ended that borrow. Reading *pos after the push wouldn't compile, because the push might reallocate.
    7. if let Some(&(parent, _)) = work.last(): destructure a shared reference to a tuple and copy out the first field.

            let (a, b) = (id_index(&e.from), id_index(&e.to));
            if members.contains(&a) && members.contains(&b) {
                adj.entry(a).or_default().insert(b);

            .windows(2)
            .map(|w| {
                let mut cands: Vec<&&Edge> = include_edges
                    .iter()

                    .collect();
                cands.sort_by_key(|e| (e.layer != prefer, e.file, e.line));
                *cands[0]
            })
            .collect();
        let break_edge = if core_only {
            *hop_edges.last().unwrap()

            hop_edges.iter().copied().find(|e| e.layer == Layer::Cust).unwrap_or(hop_edges[0])

    fn shortest_cycle(start: usize, adj: &BTreeMap<usize, BTreeSet<usize>>) -> Vec<usize> {
    let mut parent: HashMap<usize, usize> = HashMap::new();
    let mut queue = VecDeque::new();
    if adj.get(&start).is_some_and(|s| s.contains(&start)) {
        return vec![start, start];
    }
    for &v in adj.get(&start).into_iter().flatten() {
        if let std::collections::hash_map::Entry::Vacant(e) = parent.entry(v) {
            e.insert(start);
            queue.push_back(v);
        }
    }
    while let Some(u) = queue.pop_front() {
        for &v in adj.get(&u).into_iter().flatten() {
            if v == start {
                let mut path = vec![start, u];
                let mut cur = u;
                while let Some(&p) = parent.get(&cur) {
                    if p == start {
                        break;
                    }
                    path.push(p);
                    cur = p;
                }
                path.push(start);
                // path is start, u, …, start reversed in the middle
                let mut mid: Vec<usize> = path[1..path.len() - 1].to_vec();
                mid.reverse();
                let mut res = vec![start];
                res.extend(mid);
                res.push(start);
                return res;
            }
            if let std::collections::hash_map::Entry::Vacant(e) = parent.entry(v) {
                e.insert(u);
                queue.push_back(v);
            }
        }
    }
    vec![start, start]
}
    1. adj.get(&start).into_iter().flatten(): Option<&BTreeSet> becomes "the set's items, or nothing". It's the iterator version of if let.
    2. if let Entry::Vacant(e) = parent.entry(v): match on the entry enum itself and insert only when the slot is empty. One hash lookup does both the "seen?" check and the insert.
    3. VecDeque as a FIFO queue: push_back plus pop_front is breadth-first search, so the first path back to start is the shortest.

    When you have to write lifetimes

    Elision covers most functions. You have to write lifetimes out when the compiler can't tell which input an output borrows from. The rules:

    1. Each elided input reference gets its own lifetime.
    2. If there's exactly one input lifetime, every output gets it.
    3. If one input is &self or &mut self, outputs get self's lifetime.

    With two reference inputs and no self, none of these apply, and leaving the lifetime off is error E0106.

    Patterns to reuse

    The borrow-checker techniques this codebase uses again and again, collected in one place. When the compiler rejects something in your own code, it's usually one of these.

    ProblemTechniqueWhere
    Structs that refer to each otherArena: one owner (Index) with Vecs, links stored as usize or string ids
    Read one thing while building anotherKeep the data being built in a local variable and move it into the struct at the end
    A closure blocks later changesPass the borrow as a closure parameter instead of capturing it
